# Sandbox authentication repair

Observed successful email OTP requests and a GET /verify redirect, with no subsequent portal request in that attempt. The old frontend ignored the returned access token. The sandbox now accepts Supabase implicit-link callbacks, strips credentials from the URL immediately, validates the session with Supabase Auth, shows the verified account for explicit confirmation, and keeps only the access token in tab-scoped sessionStorage for same-tab reload. No refresh token is stored. Expired/used links show a clear message; workspace load failures offer retry instead of asking for email again. The OTP path remains. No SMTP, DNS, database, production or billing changes. Browser and authenticated end-to-end testing required; JavaScript syntax checked.
