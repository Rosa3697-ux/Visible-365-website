**Not live.** This branch includes a working-in-principle server API, SQL migration and bilingual workspace. No database provisioned; no credentials or real customer data; no Stripe catalog created yet. Unit tests are authored, not run in the GitHub connector. Do not merge.

## Setup gates
1. Connect Supabase, create a dedicated sandbox project, apply and inspect migration, configure verified email OTP template with actual token (not magic-link only), email delivery and abuse rate limits. MFA enrollment for admins via Supabase Auth must be implemented and tested before using Admin UI (currently requires existing MFA-authenticated access token, so admin UI is gated). Use test accounts only.
2. Stripe sandbox: tax settings pending (head office missing; zero registrations). Owner confirms exact registered jurisdiction(s), business address in Stripe Dashboard, Website Design and Website Hosting classifications (bundled managed service requires tax review), exclusive pricing and terms. Register only existing legal registrations. Create four prices/products after approval, validate automatic tax test calculation. No live mode.
3. Netlify branch/deploy preview: existing publish folder GitHub/Visible-365-website and root netlify/functions. Set function-scoped, preview-only environment variables WAAS_SANDBOX_ENABLED=true, WAAS_ORIGIN (exact preview origin), SUPABASE_URL, SUPABASE_ANON_KEY, SUPABASE_SERVICE_ROLE_KEY, STRIPE_SECRET_KEY (test), STRIPE_WEBHOOK_SECRET, STRIPE_ESSENTIAL_SETUP_PRICE, STRIPE_ESSENTIAL_MONTHLY_PRICE, STRIPE_GROWTH_SETUP_PRICE, STRIPE_GROWTH_MONTHLY_PRICE, STRIPE_PORTAL_CONFIG, WAAS_TERMS_VERSION, WAAS_TERMS_URL, WAAS_ADMIN_IDS. Leave WAAS_TAX_READY off until tax verification. No secrets in repo. Configure Stripe signed webhook at /.netlify/functions/waas and specified lifecycle events. 
4. Test node --test tests/waas.test.mjs after copying test file or using provided command (node --test netlify/functions/waas.test.mjs if co-located; actual test in tests imports ../netlify/functions/waas.mjs). Test auth, expiry, two-account isolation, admin MFA, checkout retries/expired sessions, successful/failed/canceled subscription, out-of-order events, tax, duplicate webhooks, mobile and accessibility. No production access.

Before full launch: implement admin MFA enrollment/challenge UI, durable secure session recovery, rate limiting, atomic checkout state and retries/reconciliation, webhook order/race hardening, transactional audit, private upload malware scanning, design approval audit, request allowance metering by billing cycle, client messaging and onboarding file workflow.
