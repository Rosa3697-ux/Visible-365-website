# Visible365 WaaS foundation — staged prototype

Production main remains untouched. Open waas-preview/index.html within the existing publish directory on this branch. It is a noindex, bilingual, responsive demonstration; no network submissions, payment collection, credentials, or persistent account data. The current public inquiry flow remains intact.

## Proposed experience
- Select Essential (3 pages, one language, $299 setup + $149/mo, 30 min edits) or Growth (5 core pages bilingual, $499 + $249/mo, 60 min edits); Signature unavailable.
- Sign in with verified email, confirm contact and business details, language, domain ownership, scope, revision policy and agreed terms. A scoped order must exist before payment.
- Proposed first invoice combines setup plus first month ($448 / $748 before tax). Decide billing start, cancellation, refunds, delivery timeline, and terms before activating checkout. No promises are implied by prototype.
- Hosted Stripe Checkout subscription with fixed server-side price IDs (one-time setup and recurring monthly), customer mapping, idempotency key and signed webhook verification. Never trust return URL or browser-supplied amounts. Store event IDs; reconcile subscriptions and paid invoices; handle failed payments and cancellation. Stripe customer portal for invoices, payment methods, and cancellation within approved terms.
- Auth and private records via Supabase; verified email OTP/magic link, organization membership and role checks. RLS on every client-facing table and private storage bucket. No credentials or service-role key in public repo/browser. Use Netlify function-scoped secrets; isolate test and live environments. Use private signed upload URLs, file size and MIME restrictions, rate limits, malware controls before viewing uploads. Admin uses separate privileged access with MFA.
- Client portal: current website, onboarding checklist, milestones, design review/approval, request changes, included time, billing and support. Start with manual project status and request handling; Duda comes last. Separate business admin workflow for onboarding, approvals, request assignment, time, payment state and publication.
- Proposed data model: accounts, memberships, business_profiles, orders, terms_acceptances, projects, assets, change_requests, messages, time_entries, billing_customers, subscriptions, webhook_events. Server-only billing writes. Track revisions and audit events; no client cross-account access. 
- Before production: Stripe test checkout and duplicate/failed webhook tests; two-user isolation tests; signed upload validation; mobile and keyboard tests; cancellation/refund and taxes review; written privacy policy/terms and support expectations; verify real email delivery; verify Netlify functions and test-to-live separation; no raw payment card entry in Visible365. Only merge after review and test gates.
